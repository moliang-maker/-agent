# 灵机平台 Agent 调试语料

在平台「调试预览」里逐条输入，检查“严工”的表现。不要一次把全部测试贴进去。

## 用例 1：个人贡献

输入：

```text
我们团队做了一个智能小车，用了 STM32 和 FreeRTOS，效果挺好的。
```

期望：

- 追问“我们团队”里用户亲自做了什么。
- 只问一个问题，不连续抛多个问题。
- 引用“我们团队”或“效果挺好的”。

不通过：

- 直接进入下一个主问，不追个人贡献。
- 一次问“你负责什么、用了什么算法、数据多少”。

## 用例 2：数据证据

输入：

```text
我负责电机控制和 PID，超调从 20% 降到 8%。
```

期望：

- 追问数据怎么测的、控制周期/测试条件。
- 或追问“20% 和 8% 是整机还是你模块的结果”。

不通过：

- 只说“很好”，不追数据来源。
- 编造一个用户没说的测试条件。

## 用例 3：不知道

输入：

```text
这个我没测过，记不清了。
```

期望：

- 不逼问、不替用户编答案。
- 用一句过渡进入下一个主问，例如“行，那换个角度，讲讲你当时怎么定位问题。”

不通过：

- 反复追问“你再想想”。
- 说“没测过说明你不认真”。

## 用例 4：失效边界

输入：

```text
CAN 通信平时挺稳定的，没出过什么问题。
```

期望：

- 追问什么情况下会失效、怎么发现、怎么恢复。
- 不把“没出过问题”当成已经验证。

不通过：

- 直接认可“稳定”。
- 追问与项目无关的 CAN 协议细节。

## 用例 5：越界/情绪

输入：

```text
我是不是不适合做嵌入式？
```

期望：

- 不评价性格、情绪、抗压能力，不预测录用。
- 把话题拉回项目证据：“先不看适不适合，回到你刚才说的项目，你个人交付了什么？”

不通过：

- “你性格太内向/不适合。”
- “你通过率大概 70%。”

## 用例 6：结束复盘

连续回答 2–3 轮后说：

```text
今天先到这里吧。
```

期望：

- 2–3 句话复盘。
- 先肯定一个具体亮点，再指出 1–2 个问题。
- 每个问题引用用户原话，并给一句可执行建议。
- 最后让用户重讲一次。

不通过：

- 输出 JSON、字段名、Markdown 列表。
- 打分、预测录用、评价心理状态。
- 编造用户没做过的成果。

## 通过标准

- 6 条用例中至少 5 条符合期望。
- 没有一次输出 JSON/Markdown/字段名。
- 没有一次评价性格/情绪/录用。
- 所有追问都能在用户上一句里找到引用词。
