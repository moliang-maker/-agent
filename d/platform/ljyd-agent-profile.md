# 灵机一动平台 Agent 配置包（D）

- 日期：2026-10-29
- 平台：https://platform.ljyd.cn/workSpace
- 依据：平台公开文档《三、智能体配置指南》《四、平台能力接入与集成》
- 结论：**平台是 UI 配置的语音 Agent，公开文档没有“自定义 HTTP Agent / JSON 输出”入口。**
  - 平台侧走原生 Agent：角色定义 + 对话模型 + 开场白 + 记忆 + ASR/TTS。
  - D 的 `POST /api/agent` 继续服务 A 的网页和 C 的提醒联调，不直接挂进平台。
  - 不要把 D 的 JSON 契约原样粘贴到平台角色定义里；平台会把它当台词念出来。

## 1. 平台字段填写

| 平台字段 | 建议值 |
|---|---|
| 名称 | `难开口陪练` |
| 角色昵称 | `严工` |
| 角色定义 | 粘贴 `d/platform/ljyd-role-definition.txt` 全文 |
| 默认对话模型 | 选平台可用的较强中文对话模型；若只有轻量模型，先用轻量模型跑通，再换强模型 |
| 开场白 | `先花一分钟介绍这个项目，重点说你个人负责的部分。` |
| 结束语 | `今天先到这里。按刚才的两点，把项目介绍重讲一遍。` |
| 安抚词 | `我想一下，稍等。` |
| 打断策略 | 允许用户打断；被打断后停止当前输出，先听用户说 |
| 语气 | 专业、沉稳、略压迫 |
| 随机性 | `0.7`（平台字段名可能是“随机性/温度”） |
| 内容长度 | 简洁 |
| 上下文记忆 | 开启 |
| 长期记忆 | 关闭（第一版不保存个人偏好） |
| 语音识别 | 中文；需要时中英文 |
| 音色 | 沉稳男声/女声均可，先试听 |
| 语速 | `1.0` |
| 表达风格 | 自然/沉稳 |
| 知识库 | 不挂载 |
| 插件 | 不挂载（第一版不需要天气/闹钟/设备控制） |
| 垂类模型 | 不启用 |
| 工作流 | 关闭（先用默认对话模型） |

## 2. 创建步骤

1. 登录平台，进入「智能体 > 我的智能体」。
2. 点「+ 创建智能体」。
3. 填名称、角色昵称；角色定义粘贴 `ljyd-role-definition.txt`。
4. 配默认对话模型、开场白、结束语、语气、随机性、内容长度。
5. 开启上下文记忆，关闭长期记忆。
6. 配 ASR/TTS；先试听音色和语速。
7. 不挂知识库、插件、垂类模型；工作流先关闭。
8. 进入「调试预览」，用 `ljyd-test-cases.md` 的语料跑一遍。
9. 保存草稿 → 发布新版本 → 在创建产品时绑定这个智能体。
10. 设备端由 B 按平台产品/PID/SDK 流程接入；D 不直接改 B 固件。

## 3. 平台对话的预期表现

- 第一问只问项目介绍，不一次抛三个问题。
- 听到“我们团队”会追问个人贡献。
- 听到“效果很好”会追问数据。
- 候选人说“不知道”会过渡到下一问，不逼问。
- 结束给 2–3 句复盘，引用原话，不评分、不预测录用。
- 不出现 JSON、字段名、Markdown 列表。

## 4. 与 D 现有接口的关系

| 使用方 | 走什么 | 说明 |
|---|---|---|
| A 网页 | `POST /api/agent` | D 的 JSON 契约、Mock/真实 Agent |
| C 视觉提醒 | `GET /api/agent/state` | 只判断 `reminder_allowed` |
| 灵机平台设备 | 平台原生 Agent | 平台负责 ASR/TTS/模型/设备绑定，不走 D 的本地 HTTP |

两条链路共用同一套人设和追问规则，但**输出形态不同**：平台说人话，D 返回 JSON。

## 5. 需要平台侧确认

- [ ] 平台是否支持“自定义模型 Base URL / API Key”（若支持，可把 D 的模型层接进去）。
- [ ] 平台是否支持结构化输出/JSON（当前公开文档未提）。
- [ ] 平台是否支持工作流里调用自定义 HTTP（当前节点列表没有 HTTP 节点）。
- [ ] 平台产品的 PID 和绑定方式（由 B/平台侧完成）。
